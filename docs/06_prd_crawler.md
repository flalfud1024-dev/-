## 1. 개요(Overview)

### 1.1 시스템명
`vegetarian-douban-crawler` — 한강 『채식주의자』 중문 번역본 3종의 豆瓣 독자 리뷰 자동 수집 시스템

### 1.2 한 문장 요약
> 박사학위논문 텍스트마이닝 분석을 위해, 3개 번역본의 豆瓣 독자 리뷰를 **재현 가능하고 윤리적으로** 수집하는 도구.

### 1.3 작성 배경
- 1차 수집된 리뷰가 존재하나, 표본 크기 불균형·메타데이터 누락 가능성 존재
- 연구 1·2·3 통계 검증을 위해 번역본별 N≥200 표본 확보 필요
- 1차 수집 절차의 재현성 부족 → 논문 부록 5에 수록할 표준화된 수집 시스템 필요

### 2.1 연구 맥락

|--------|--------------------|--------|

### 2.2 목적(Goals)
- **G1**: 3개 번역본 각각 최소 200건 이상의 유효 리뷰 확보
- **G2**: 모든 수집 작업이 단일 명령으로 재실행 가능 (부록 코드 첨부)
- **G3**: 豆瓣 이용약관 및 robots.txt 준수
- **G4**: 사용자 식별정보 익명화 처리(IRB 윤리)

### 2.3 비목적(Non-Goals)
- 豆瓣 외 플랫폼(微博, 小红书 등) 수집 — v2.0 이후 검토
- 영상·이미지 등 비텍스트 데이터 수집
- 실시간 모니터링 — 일회성 스냅샷 수집

## 4. 범위(Scope)

### 4.1 In-Scope
- ✅ 3개 도서 페이지의 短评(short review) 수집
- ✅ 3개 도서 페이지의 影评/書評(long review) 수집
- ✅ 리뷰 메타데이터 (별점, 작성일, 좋아요 수)
- ✅ 사용자 ID 해싱 익명화
- ✅ 수집 로그 및 원본 HTML 스냅샷 저장
- ✅ 중복 제거 및 기본 정제

### 4.2 Out-of-Scope
- ❌ 사용자 프로필·팔로워 정보
- ❌ 댓글의 댓글(reply-of-reply)
- ❌ 비공개·로그인 필요 콘텐츠 강제 접근
- ❌ Captcha 자동 우회
- ❌ IP 우회·VPN 통한 차단 회피

## 5. 기능 요구사항(Functional Requirements)

### FR-1: 도서 페이지 정의
- 3개 번역본의 豆瓣 도서 ID를 `config.yaml`에 명시
- ID 변경 시 코드 수정 없이 설정만으로 대응

### FR-2: 短评 리스트 페이지 수집
- 페이지네이션 자동 순회 (최대 페이지 한도 설정 가능)
- 각 페이지당 요청 간격: **3~5초 무작위 지연**
- 응답 코드 200 외 발생 시 재시도 ≤ 3회 (지수 백오프)

### FR-3: 影评 상세 페이지 수집
- 短评 리스트에서 영평 링크 추출
- 상세 페이지 본문 + 메타데이터 수집

### FR-4: 데이터 추출 항목
**필수**:
- `review_id` (豆瓣 내부 ID)
- `version` (번역본 식별자)
- `user_id_hash` (SHA-256 해시, salt 포함)
- `rating` (1~5점 또는 None)
- `text` (리뷰 본문)
- `date` (작성일, ISO 8601)
- `likes` (유용 카운트)
- `crawl_timestamp` (수집 시각)

**선택**:
- `reply_count`
- `is_long_review` (短评/影评 구분)
- `review_url`

### FR-5: 익명화 처리
- 사용자 ID는 SHA-256 + 비공개 salt로 해싱
- 본문 내 명시적 개인정보(전화번호·이메일) 정규식 마스킹
- 익명화 키(salt)는 로컬 환경변수로 관리, 코드/저장소에 미포함

### FR-6: 중복 제거
- `review_id` 기준 1차 중복 제거
- 텍스트 fuzzy matching (Levenshtein ≤ 0.05)으로 표절·재게시 2차 제거

### FR-7: 로그 기록
- 모든 HTTP 요청·응답·재시도 로그
- 수집 세션별 요약 통계 (총 요청 수, 성공/실패, 소요 시간)
- 원본 HTML 스냅샷 저장 (재현성·검증용)

### FR-8: 출력 형식
- `data/raw/<version>_<YYYYMMDD>.csv` (UTF-8 BOM, Excel 호환)
- `data/raw/_logs/<version>_<YYYYMMDD>.log`
- `data/raw/_snapshots/<version>/<page>.html`

## 6. 비기능 요구사항(Non-Functional Requirements)

### NFR-1: 윤리 및 법적 적합성 (최우선)
- **robots.txt 준수**: 수집 전 `https://www.douban.com/robots.txt` 확인 및 로그
- **요청 빈도 제한**: 페이지당 3~5초 무작위 지연, 분당 ≤ 20 요청
- **User-Agent**: 정상 브라우저 식별자 단일 고정 (위장·로테이션 금지)
- **인증 우회 금지**: 비공개 콘텐츠 접근 시도 금지
- **연구목적 명시**: User-Agent 또는 contact 헤더에 연구자 이메일 포함 권장
- **IRB 검토**: 학교 연구윤리심의 면제 여부 사전 확인

### NFR-2: 재현성
- 패키지 버전 고정 (`requirements.txt`)
- 랜덤 시드 고정 (`RANDOM_SEED = 42`)
- 수집 시각 메타데이터 의무 기록
- 단일 명령 실행 가능 (`python crawl.py --version all`)

### NFR-3: 안정성
- 네트워크 단절 시 마지막 성공 페이지부터 재개(resume) 기능
- 부분 실패 시에도 수집된 데이터는 즉시 디스크에 flush

### NFR-4: 성능
- 번역본 1개당 1,000건 수집 시 1시간 이내 완료 (지연 시간 포함)
- 메모리 사용량 ≤ 1GB

### NFR-5: 보안 및 프라이버시
- 익명화 salt는 환경변수, 절대 커밋 금지 (`.gitignore`)
- 원본 사용자 ID는 디스크에 저장 금지
- 출판 시 모든 데이터셋은 익명화 검증 후 공개

## 7. 데이터 스키마(Data Schema)

```yaml
review:
  review_id:        string         # 豆瓣 고유 ID
  version:          enum           # tianyi_2013 | taiwan_2016 | huchutong_2021
  user_id_hash:     string         # SHA-256(user_id + salt)
  rating:           int | null     # 1~5, 미평점 시 null
  text:             string         # 리뷰 본문 (정제 전)
  text_clean:       string         # 정제 후 (개인정보 마스킹)
  date:             ISO 8601       # 2024-03-15
  likes:            int
  reply_count:      int
  is_long_review:   bool
  review_url:       string
  crawl_timestamp:  ISO 8601
  source_html_path: string         # HTML 스냅샷 경로
```

## 8. 기술 스택(Tech Stack)

> 자문 자료 수령 후 v1.0에서 확정

### 8.1 후보 비교

| 도구 | 장점 | 단점 | 권장 시점 |
|------|------|------|-----------|
| **requests + BeautifulSoup** | 가볍고 투명, 학습 용이 | 동적 콘텐츠 불가 | 1차 권장 |
| **Selenium / Playwright** | 동적 렌더링·로그인 처리 | 무겁고 탐지 위험 | 동적 페이지 발견 시 |
| **Scrapy** | 대규모·비동기 효율 | 학습 곡선·과한 추상화 | 미권장 (소규모) |

### 8.2 보조 라이브러리
```
requests==2.31.0
beautifulsoup4==4.12.0
lxml==4.9.0
pyyaml==6.0
tenacity==8.2.0       # 재시도 로직
python-Levenshtein    # 중복 제거
tqdm                  # 진행률
```

## 11. 위험 및 완화(Risks & Mitigations)

| 위험 | 영향 | 완화 |
|------|------|------|
| 豆瓣 IP 차단 | 수집 중단 | 지연 강화, 단일 IP 정상 사용, 차단 시 즉시 중지 |
| 페이지 구조 변경 | 파서 실패 | HTML 스냅샷 저장 → 사후 재파싱 가능 |
| 로그인 필수 페이지 등장 | 일부 데이터 손실 | 공개 영역만 수집, 한계로 논문 명시 |
| 중복·스팸 리뷰 | 분석 노이즈 | FR-6 이중 중복 제거 |
| ToS 위반 우려 | 윤리·법적 문제 | 자문 + IRB 검토 + 학술 공정사용 검토 |
| 표본 크기 부족 | 통계 검증 약화 | 사전 N 산정, 부족 시 분석 범위 조정 |

## 12. 수용 기준(Acceptance Criteria)

본 PRD가 충족되었다고 판단하는 객관적 기준:

- [ ] 3개 번역본 모두에서 최소 200건 유효 리뷰 수집
- [ ] 데이터 스키마 9개 필수 필드 결측률 ≤ 5%
- [ ] 익명화 검증: 원본 user_id 흔적 0건
- [ ] 동일 명령 재실행 시 동일 데이터셋(타임스탬프 제외) 산출
- [ ] 단위테스트 커버리지 ≥ 80% (파서·익명화 모듈)
- [ ] 수집 로그 전체 보존 (오류·재시도 포함)
- [ ] robots.txt 준수 로그 확인 가능
