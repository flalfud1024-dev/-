# AI 활용 공시 및 연구 진실성

## 학계의 현재 기준 (2024~2025년 추세)

| 사용 방식 | 허용 여부 | 표기 방법 |
|-----------|-----------|-----------|
| AI가 생성한 코드를 연구자가 이해하고 검증하여 사용 | ✅ 허용 | 방법론 각주에 명시 |
| AI를 공동저자나 자문자로 표기 | ❌ 불가 | - |
| AI 사용 사실을 아예 미표기 | ❌ 불가 | 연구윤리 위반 소지 |
| AI 코드를 이해 없이 그대로 제출 | ❌ 위험 | 심사 질문 대응 불가 |

한국연구재단 및 대부분의 국내외 학술지는 2024년 이후 **AI 사용 공시 의무화** 추세.

## 논문 각주 표기 (최종안)

본 연구에서 채택한 협업 구조:

```
Claude (AI)                데이터사이언스 전문가        연구자 (본인)
──────────                 ──────────────────          ──────────────
코드 초안 생성         →   방법론 타당성 검증      →   최종 이해·수정·검증
빠른 프로토타이핑          통계 선택 근거 자문          논문 책임 주체

```

### 방법론 챕터 각주 (표준안)

> 본 연구의 텍스트마이닝 분석 파이프라인 구축 과정에서 AI 언어모델(Claude, Anthropic, 2025)을 코드 생성 보조 도구로 활용하였으며, 생성된 코드 전체는 데이터사이언스 전문가의 자문을 거쳐 연구자가 직접 검토·수정·검증하였다. 최종 분석 코드는 부록 2에 수록하였다.

### 감사의 글 표기 (관례)

> 본 연구의 정량 분석 방법론 자문에 도움을 주신 ○○○ 선생님(서울대학교 ○○학과)께 깊이 감사드린다.

## 왜 "데이터사이언스 자문"으로 AI를 표기하면 안 되는가

- Claude는 **학술적 책임을 질 수 있는 주체가 아님**
- 심사위원회에서 **연구 진실성(Research Integrity)** 문제로 직접 지적받을 수 있음
- AI는 저자 자격(authorship) 기준인 ① 지적 기여, ② 책임성, ③ 동의를 충족할 수 없음 (ICMJE, COPE 기준)

## 핵심 원칙

> **코드를 누가 짰는지가 아니라, 연구자가 방법론을 완전히 이해하고 있는지가 핵심이다.**

심사 질문 예시에 답할 수 있어야 함:
- "LDA에서 토픽 수를 왜 이 숫자로 결정하셨나요?"
- "코히런스 스코어 기준으로 최적값을 선택하셨는데, c_v 말고 다른 지표는 왜 안 쓰셨나요?"
- "Mann-Whitney U를 쓴 이유가 뭔가요? t-검정은 왜 안 되나요?"
